# Release Notes

v1.9.0 makes downstream MCP servers usable without pass-through auth, stops stdio servers from inheriting the gateway's environment, keeps downstream URLs and raw errors away from agents, and lets CEL rules use the `tool` variable the docs show.

---

## Breaking Changes

### Stdio servers no longer inherit the gateway's environment

A stdio downstream server used to get every environment variable the gateway had, including AI provider keys and other credentials. It now gets only `PATH`, `HOME`, `USER`, `LOGNAME`, `SHELL`, `TERM`, `TMPDIR`, `LANG` and `LC_ALL` (the Windows equivalents on Windows), plus what you list in its new `env` field.

If a stdio server needs anything else, list it under `env`. Use `${VAR}` to pass a variable through from the gateway's environment:

```yaml
downstream_mcp_servers:
  github:
    type: stdio
    command: npx
    args: ["-y", "@modelcontextprotocol/server-github"]
    env:
      GITHUB_PERSONAL_ACCESS_TOKEN: "${GITHUB_PERSONAL_ACCESS_TOKEN}"
```

Or via environment variable:

```bash
export MAYBE_DONT_DOWNSTREAM_MCP_SERVERS_GITHUB_ENV_GITHUB_PERSONAL_ACCESS_TOKEN=ghp_xxx
```

Proxy and certificate settings such as `HTTPS_PROXY` and `NODE_EXTRA_CA_CERTS` are not inherited, because proxy URLs can contain credentials. Pass them through the same way if `npx` or `uvx` needs them. `env` is only valid on stdio servers, and the gateway refuses to start if it's set on an http or sse server.

See [Downstream Servers](https://maybedont.ai/docs/mcp-gateway/downstream-servers/).

### `server.sse.tls` is removed

The gateway never served TLS, even with `server.sse.tls.enabled: true`. The setting is now rejected at startup, including `enabled: false` and the `MAYBE_DONT_SERVER_SSE_TLS_*` environment variables, with this message:

```
server.sse.tls is not supported and has been removed; terminate TLS in a reverse proxy in front of the gateway, then remove server.sse.tls from your config
```

Delete the `server.sse` block from your config and put a reverse proxy in front of the gateway if you need HTTPS. See [Server Modes](https://maybedont.ai/docs/mcp-gateway/server-modes/).

### A config file that can't be read stops startup

Before, a config file with a YAML error, or one the gateway couldn't read, was silently ignored and the gateway started with defaults. It now refuses to start and prints the file path with the parser error:

```
failed to read config file /path/to/maybe-dont.yaml: <parser error>
```

A missing config file still falls back to defaults as before.

### CEL rules keep evaluating after a rule errors

When a CEL rule failed to evaluate, for example because it read a field the request didn't have, the gateway skipped every rule after it and allowed the call. It now skips only the rule that errored and evaluates the rest, so a later `deny` rule still blocks the call. A call with no deny is still allowed and logged as `fail_open`. This applies to MCP tool calls, CLI commands and response rules.

## New

### `tool` variable in CEL policies

CEL rules can now use `tool.name` and `tool.arguments`, as the policy docs show. Before, a rule written that way stopped the gateway from starting with `undeclared reference to 'tool'`. `request.params.name` and `request.params.arguments` still work and mean the same thing.

```yaml
- name: no-file-deletes
  mcp_expression: tool.name == "github__delete_file"
  action: deny
  message: "Deleting files is not permitted"
```

## Fixed

- Tools, prompts and resources on stdio servers and on HTTP servers with static headers now work. Before, calls failed with "client '<name>' not connected for this session" unless the caller sent pass-through credentials. Downstream servers now connect for a session the first time a call uses them, after policy validation.
- Prompts and resources are proxied for every downstream server that advertises them. Before, they only appeared when the server also sent change notifications.
- An http downstream that answers the MCP initialize request with a 4xx, which is how GitHub answers a bad token, now fails with "rejected the MCP initialize request with a 4xx status; check its credentials (headers or pass-through auth) and URL". Before, the error said the server might need `type: sse`.
- Agents no longer see downstream URLs, query strings or raw connection errors. `maybedont__list_downstream_servers` returns the URL without credentials, query or fragment. `maybedont__discover_tools` and failed tool calls, prompts and resources return a fixed message such as "call to downstream server 'github' failed; see the gateway log for details". A 401 says which credentials to check. Errors the downstream server returns itself still reach the agent unchanged.
- URLs in gateway logs, including those from the MCP client library, have credentials and query strings removed.
- Starting without an AI API key now names every setting to turn off. With the default config that's `request_validation.ai.enabled` and `native_tools.audit_report.enabled`. The default config also sets `validation.ai.provider: openai`, which removes the deprecation warning printed on every start.
