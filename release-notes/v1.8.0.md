# Release Notes

v1.8.0 stops downstream MCP servers from redirecting the gateway to other hosts, and adds a per-server option to allow it for servers you trust.

---

## Breaking Changes

### Cross-origin redirects from downstream servers are refused

HTTP and SSE downstream servers can now only redirect the gateway to the same host and port. Path changes and `http://` to `https://` upgrades on the same host still work. A redirect to a different host, a different port, or from `https://` down to `http://` fails, and the error names both addresses.

Previously the gateway followed any redirect and sent your configured headers, including API keys and pass-through credentials, to the new host. A redirect could also point the gateway at internal addresses such as a cloud metadata service.

If a server you trust needs to redirect to another host, set `url` to the final address, or allow it for that server:

```yaml
downstream_mcp_servers:
  vendor:
    type: http
    url: "https://old.vendor.example/mcp"
    allow_cross_origin_redirects: true   # default: false
```

Or via environment variable:

```bash
export MAYBE_DONT_DOWNSTREAM_MCP_SERVERS_VENDOR_ALLOW_CROSS_ORIGIN_REDIRECTS=true
```

See [Downstream Servers: Redirects](https://maybedont.ai/docs/mcp-gateway/downstream-servers/#redirects).

---

## Security

- Mitigates GO-2026-6911 in `mark3labs/mcp-go` (header leak and SSRF through redirects) with the change above. There is no upstream fix yet.
- Upgrades `google/cel-go` to v0.30.0 for GO-2026-6094. The gateway didn't use the affected code.
