# Release Notes

v1.6.1 fixes tool discovery reliability after transport reconnects, ensuring MCP clients always have an up-to-date tool registry.

---

## Fixed

### Tool registry out of sync after `discover_tools`

After calling `discover_tools` (e.g., to authenticate a pass-through client), MCP clients were not notified that the tool list had changed. This caused two problems:

- **Stale tool list**: Clients kept their cached tool list and never saw newly discovered tools until they manually refreshed.
- **Missing handlers after reconnect**: If the gateway restarted or the transport reconnected, tools appeared in `tools/list` but calls to them failed because handlers were not registered for the requesting session.

The gateway now sends a `tools/list_changed` notification to the session after `discover_tools` completes, and ensures tool handlers are registered globally for already-connected clients.
