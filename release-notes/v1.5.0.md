# Release Notes

v1.5.0 ships embedded hook scripts for five AI agents — Claude Code, Cursor, Gemini CLI, Cline, and GitHub Copilot — so you can enforce gateway policies on agent tool calls without running the MCP proxy.

---

## New

### Agent Hook Scripts

Self-contained bash hook scripts are now embedded in the binary for five AI agents. Each script calls the gateway's `POST /api/v1/intercept` endpoint (introduced in v1.4.0) before and after tool execution, enabling policy enforcement on shell commands, MCP calls, or both.

Supported agents:

| Agent | Hook Events |
|-------|-------------|
| **Claude Code** | PreToolUse / PostToolUse |
| **Cursor** | Shell execution / MCP execution hooks |
| **Gemini CLI** | BeforeTool / AfterTool |
| **Cline** | PreToolUse / PostToolUse |
| **GitHub Copilot** | PreToolUse / PostToolUse |

All scripts require the `MAYBE_DONT_URL` environment variable pointing to a running gateway. If the gateway is unreachable or returns a non-2xx status, scripts fail open so agent workflows are not blocked.

These scripts are reference implementations — the intercept endpoint is a standard REST API, so you can write your own hooks in any language and integrate any agent that supports pre/post-execution hooks.

### Response-Phase Limitations

Pre-tool hooks can block tool execution. Post-tool hooks are limited by what each agent allows after execution has completed:

| Agent | Request deny | Response deny | Response redact |
|-------|:---:|:---:|:---:|
| **Claude Code** | Block | Audit only | No |
| **Cursor** (shell) | Block | Audit only | No |
| **Cursor** (MCP) | Block | Audit only | Redact |
| **Gemini CLI** | Block | Audit only | No |
| **Cline** | Block | Audit only | No |
| **GitHub Copilot** | Block | Audit only | No |

Cursor's `afterMCPExecution` hook is the only path that supports response redaction — the script returns the gateway's redacted content via `updated_mcp_tool_output`. All other post-tool hooks log a warning to stderr when the gateway flags a violation but cannot modify or withhold the output.

Note: the gateway audit log records the policy decision as-is (e.g., `action: "deny"`), even when the hook cannot enforce it. Audit entries from hooks use `source: "intercept"` to distinguish them from MCP proxy validation where denials are enforced.

### `hooks` CLI Command

A new `maybe-dont hooks` command lets you list available hook scripts and export them for installation:

```bash
# List available agents
maybe-dont hooks list

# Export the hook script
maybe-dont hooks export --agent claude-code > maybe-dont-hook.sh
chmod +x maybe-dont-hook.sh

# Export the agent's config snippet
maybe-dont hooks export --agent claude-code --config
```

The config snippets are ready-to-use JSON that you can merge into each agent's configuration file. Update the script path and set `MAYBE_DONT_URL` in your environment.
