# Release Notes

v1.5.1 adds an explicit `enforce` policy mode and upgrades Go to 1.25.8, resolving seven stdlib vulnerabilities.

---

## New

### Explicit `enforce` Policy Mode

Previously, switching from `audit_only` to enforcing mode required setting mode to an empty string — awkward in YAML and impossible via environment variables. You can now use `mode: enforce` explicitly:

```yaml
request_validation:
  cel:
    enabled: true
    mode: enforce  # rules can now block requests
```

Or via environment variable:

```bash
export MAYBE_DONT_REQUEST_VALIDATION_CEL_MODE=enforce
```

This works at both the top-level phase and per-rule level. The empty-string behavior still works for backwards compatibility, but `enforce` is now the recommended way to enable blocking.

Invalid mode values (anything other than `audit_only` or `enforce`) are now rejected at startup with a clear error message, including per-rule modes.
